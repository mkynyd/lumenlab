## 文档、图像与存储边界

| 入口 | 识别与模型输入 | 保存范围 |
|---|---|---|
| 项目资料 | PDF 走 MiniMax M3.1，必要时回退 MinerU；Office 走 MinerU；文本与代码本地读取；图片标记 `direct-image` 后交给所选模型 | 原文件与解析正文、文档内图片资源长期保存，文本分块可建立关键词与向量索引 |
| 聊天附件 | PDF/DOCX 优先提取正文，扫描 PDF 转为有数量上限的页图；图片直接进入多模态调用 | `MessageAttachment` 关联会话与消息，保存原对象和元数据；图片另生成缩略图，历史读取重新校验归属 |
| 学习扫描选题 | 图片、PDF、Office 先生成临时预览，用户框选完整题目后才进入识别、解答与核验 | 完整预览在提交、取消或过期后清除，长期保留所选题目裁片、文字、解析与必要素材 |

生产使用私有对象存储，开发可使用本地存储。数据库记录存储位置、尺寸、状态与归属，下载通过鉴权接口完成。选题素材的 staging 清单、临时预览和清理任务独立管理。

聊天附件的持久化用于历史展示，PDF/DOCX 的正文提取在请求内完成。项目图片通过模型直接理解，文本检索索引覆盖可提取的正文。学习扫描的运行依赖和清理规则见[部署](../deployment.md#学习扫描与文档导出依赖)。

## 资料生命周期

上传资料后会进入解析流程：

1. 写入存储并创建资料记录，状态为「解析中」。
2. 解析成功后状态变为「解析完成」，可被对话引用。
3. 解析失败则状态为「解析失败」，可重试或换一份文件上传。

知识增强有独立的状态：未增强 / 增强中 / 已增强 / 过期 / 失败。

## 支持的资料类型

| 类型 | 说明 |
|------|------|
| PNG / JPG / WebP | 不做 OCR，上传后标记为就绪，提问时作为原始资源直接交给所选模型识别 |
| PDF（≤20MB） | MiniMax M3.1 原生文档解析，不区分文本型还是扫描型 |
| PDF（>20MB，上限 200MB） | MinerU 解析；MiniMax 请求被拒绝时也会回退 MinerU |
| DOC / DOCX / PPT / PPTX / XLS / XLSX | 自动调用 MinerU 转换为 Markdown，并保存文档内图片资源 |
| WPS / ET / DPS | 按 Office 文档处理，适合 WPS 课件和表格 |
| Pages / Numbers / Keynote | 按 iWork 文档处理，适合 macOS 课程资料 |
| Markdown / TXT / CSV / 代码文件 | 直接提取文本内容 |

上传限制：单文件 50MB，单次最多 50 个文件，总大小 300MB。

## 图片与 PDF 解析

- 图片资料不再单独做 OCR：上传后直接就绪，提问时作为原始资源交给当前选择的模型（三家活跃模型都支持图片输入）。
- PDF 资料默认走 MiniMax M3.1 原生文档解析；超过 20MB（上限 200MB）或请求被拒绝时回退 MinerU。
- 解析结果可以在文件详情页查看和简单编辑。

## Office 文档解析

- Office、WPS 与 iWork 文档使用 MinerU 解析为 Markdown。
- 解析过程中提取到的图片会保存为项目文件资源，并在 Markdown 中改写为私有资源链接。
- 该流程需要当前用户或中央凭证组配置 MinerU Token。
- 附件不会影响模型路由：无论文档类型如何，回答都由你在输入框上方选定的模型生成。

## 检索时使用的正文

- 检索与 RAG 使用的是文件的「有效正文」：文件完成过增强时取增强内容，否则取解析出的正文。
- 当前版本的文件详情页不再提供手动触发知识增强的入口，`FileAsset.enhancementStatus` 只用于展示历史文件的状态。

## 检索策略

系统会根据当前问题自动选择最合适的检索方式：

| 策略 | 触发场景 |
|------|----------|
| 不使用资料 | 普通闲聊，不需要引用项目资料 |
| 全文加载 | 用户明确针对某份小文件提问，且文件内容不超过约 8000 字符 |
| 关键词检索 | 未开启向量检索，或策略选择关键词检索 |
| 混合检索 | 关键词检索与向量检索结果融合 |

检索流程大致如下：

1. 如果你勾选了具体文件，小文件会直接全文加载，大文件则作为候选范围。
2. 如果没有明确勾选，系统会先用项目索引和关键词判断哪些资料可能与问题相关。
3. 在候选资料范围内做关键词或混合检索。
4. 针对全项目语料的任务（如提取知识点、生成复习材料）会直接使用所有已解析或部分解析的资料。

## 向量检索

- LumenLab 使用阿里云百炼 qwen3-vl-embedding 1024 维融合模式生成向量。
- 当前用户或中央凭证组配置百炼 API Key 后，解析文件时会自动生成向量。
- 混合检索会结合向量相似度和关键词匹配，返回更相关的内容。
- 设置页目前没有「向量命中率」指标。

## 资料图谱

项目侧边栏提供「资料图谱」入口。图谱按三类节点展示项目资料：

| 节点 | 含义 |
|------|------|
| topic | 从项目索引和文件摘要中提取的主题 |
| file | 项目中的资料文件 |
| chunk | 可检索的文本分块 |

点击节点可以查看类型、摘要、解析状态和相关文件。资料图谱用于理解资料覆盖范围和解析质量，不会改变原始资料内容。

## 常见问题

- 解析失败：检查文件格式与大小（单文件上限 50MB），查看文件详情页的错误提示。Office/WPS/iWork 文档还需要 MinerU Token。
- 检索为空：确认文件状态为「解析完成」，或在对话中显式勾选文件作为上下文。
- 向量检索未生效：确认当前用户或中央凭证组已配置百炼 API Key。
