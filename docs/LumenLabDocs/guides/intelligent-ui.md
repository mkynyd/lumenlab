# 智能界面

> 面向 LumenLab 普通用户与开发者 · 更新日期：2026-11-23

智能界面（Generative UI）让回答不只停留在文字。模型可以在完整正文之后，按问题生成一块可交互的内容：并排比较、步骤切换、滑杆调参、联动图表或状态序列。它和普通 Markdown 回答共用同一条消息，不替代正文结论。

## 什么时候会出现

模型会先判断问题需不需要“看见”或“动手”：

- 你明确要求可视化、画图、流程图、可交互或“让我调一下参数”。
- 问题包含多方案比较、趋势、可探索变量、顺序步骤、状态迁移或结构变化。
- 需要流程或状态图时，正文中使用 LumenFlow；需要比较或变量探索时，再追加界面。

简单定义、翻译、摘要、单步结论和纯计算仍然只用文字。界面不是“每条回答都要加”的装饰。

## 在对话里是什么样

正文先完整回答，空一行后才是界面。即使界面没有加载出来，正文也能独立读懂。下面是一个真实渲染的示例：

```smart-ui-demo
交互示例：电压恒为 6 V，拖动电阻，观察电流 I = U/R 与功率 P = U²/R 的变化。
```

示例里的数据是演示数据，界面会明确标注；真实项目数据只有在取得当前项目资料列表后才会引用。

## 能生成哪些组件

| 类型 | 用途 |
| --- | --- |
| `compare` | 两组内容并排比较，窄屏自动纵向排列 |
| `table` | 小规模数据表，可标注演示数据或项目资料 |
| `bar` / `line` | 柱状图、折线图，附带可展开的数据表 |
| `sequence` | 按比例展示区间拆分，自带前后切换 |
| `steps` | 算法或操作步骤，可绑定当前步骤 |
| `slider` / `select` / `checkbox` / `input` | 调整数值、选项和布尔状态 |
| `value` / `list` / `text` | 展示计算结果、清单和简短说明 |
| `button` | 重置状态，或把当前参数带入追问 |
| `disclosure` | 可展开的补充说明 |

一个界面最多 8 组、64 个节点、6 层嵌套。每个控件都应改变有用的结果，不重复正文已经说清的信息。

## 开启与关闭

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `CHAT_INTELLIGENT_UI_ENABLED` | `0` | 设为 `1` 后允许普通聊天和项目聊天生成并持久化界面 |
| `CHAT_INTELLIGENT_UI_RENDER` | `1` | 设为 `0` 后只显示正文，历史消息仍保留原始数据 |

如果本轮只想看文字，可以直接说“只给文字”或“不要图表”。这类明确要求会抑制界面生成。

## 性能与隐私

- 渲染器和图表按需加载；首个分组到达时会预加载，避免整段回答等最后一个组件。
- 已渲染的智能界面会匿名采样生产 INP：每次页面访问最多一条，包含随机访问 ID、UTC 日期、`narrow` / `wide` 和取整毫秒，不记录用户、路由或交互目标。
- 样本按用户限流为每小时 60 条，Redis 中保留 14 天。运维可用 `npm run diag:chat-inp -- 7` 读取最近 7 天的 P50 / P75 / P95。
- 本文档和落地页里的示例使用同一套真实渲染器，但关闭了 INP 上报，不会计入聊天面板样本。

## 限制

- 界面只能使用内置目录中的组件，不能执行任意 HTML、脚本或外部组件。
- 所有分组在服务端校验版本、大小、变量引用和预算，失败时回退为正文。
- 项目资料图表只在当前请求成功取得项目文件列表时可用。
- 交互结果用于理解和追问，不替代实验、测量或课程要求的正式计算过程。
